## 启动与排查

首次运行请先按 [项目首页](../README.md#快速开始) 安装 Node.js 并获取源码。Windows 可双击项目根目录的 `start-console.cmd`：脚本检查 Node.js 版本与 npm，缺少依赖、安装不完整或依赖版本与锁文件不一致时执行 `npm ci --include=dev`，随后构建界面并启动。依赖完整时跳过安装；安装和构建失败都不会继续启动，Windows 窗口会保留错误提示。首次安装需要联网，Node.js 或 npm 缺失时会提示安装，不自动修改系统环境。

手动启动时，在包含 `package.json` 的项目根目录执行 `npm ci --include=dev`，再执行 `npm start`。界面构建需要开发依赖，不要使用 `--omit=dev`。更新代码前先停止旧控制台，更新完成后重新运行脚本，成功启动后刷新网页。

项目根目录的 `.npmrc` 默认使用境内镜像 `https://registry.npmmirror.com`，一键启动的依赖安装和在项目目录执行的 npm 命令均会读取，无需修改用户级或全局 npm 配置。

需要临时切换安装源时，可在启动前设置 npm 环境变量。例如 PowerShell 中切回官方源（重新打开终端后恢复项目默认值）：

```powershell
$env:npm_config_registry='https://registry.npmjs.org'
$env:npm_config_replace_registry_host='always'
.\start-console.cmd
```

`replace_registry_host` 让锁文件中的既有镜像下载地址也使用所选源；只替换下载地址，依赖版本和完整性校验仍由锁文件约束。

**控制台启动前就需要游戏协议包。** 没有可读取的协议时，服务会在监听端口之前报错，无法先打开网页再扫码补齐。准备方式任选其一：

- 在本机电脑版微信打开《疯狂水世界》，等待游戏完成加载后退出游戏，让工具读取下载好的缓存。
- 自备 `_src_chunks_.wxapkg`，放入项目根目录或 `protocol/` 子目录，或用 `CW_PROTO_BUNDLE` 明确指定协议包／已解包的 `game.js`。

配置表和世界地图默认从游戏 CDN 更新，**不会同时下载协议包**。协议选择顺序与新版缺包处理见 [资源自动更新](#资源自动更新)；本机最新微信包不完整时，需要让客户端下载完整，或显式指定可用协议，单纯把旧包复制到根目录不会覆盖最新缓存的优先级。

Windows PowerShell 中可显式指定协议并启动（请替换示例路径）：

```powershell
npm.cmd ci --include=dev
$env:CW_PROTO_BUNDLE='D:\游戏协议\_src_chunks_.wxapkg'
npm.cmd start
```

使用 `npm.cmd` 可避免 PowerShell 拦截 `npm.ps1`，无需修改系统执行策略。已有可用依赖且没有更新依赖清单时，后续启动只需执行 `npm.cmd start`。环境变量仅对当前终端及其子进程生效；取消显式协议路径可运行 `Remove-Item Env:CW_PROTO_BUNDLE`。

### macOS

macOS 提供基础运行适配。安装符合项目要求的 Node.js 后，在项目根目录执行 `npm ci --include=dev`、`npm start`，默认使用系统浏览器打开控制台。自备协议可在终端中指定：

```sh
CW_PROTO_BUNDLE="/绝对路径/_src_chunks_.wxapkg" npm start
```

微信协议与配置缓存从 `~/Library/Containers/` 下的 `com.tencent.xinWeChat` 或 `com.tencent.WeChat` 容器查找，缓存根目录为 `Data/Documents/app_data/radium/users`。提示无权读取时，在系统设置的“隐私与安全性 → 完全磁盘访问”中授权当前终端，完全退出并重开终端后重试；也可使用自备协议包。需要本地配置表时，可另设 `CW_CONFIG_PACK` 指向完整配置 JSON。

电脑微信和电脑抖音采集仅适用于 Windows。Mac 可使用支付宝扫码、益世界 APP 手机号登录或账号导入；微信原生扫码的实现和现有验证范围见 [微信原生扫码登录](wechat-native-login.md)。

### 常见启动问题

| 现象 | 处理方法 |
| --- | --- |
| 找不到 `node` / `npm`，或提示 Node.js 版本不支持 | 安装项目要求的 Node.js 后重开终端，用 `node -v` 检查当前版本 |
| 找不到 `esbuild`、`vite` 等命令或模块 | 确认位于项目根目录，重新执行 `npm ci --include=dev`（PowerShell 可用 `npm.cmd ci --include=dev`），成功后再启动 |
| 缺少协议、最新微信包缺分包，或协议解码失败 | 按上面的准备步骤更新完整游戏包；自备协议用 `CW_PROTO_BUNDLE` 指定，确认路径及版本有效 |
| `EADDRINUSE` / 端口已占用 | 若已有控制台，直接打开其地址，或关闭旧控制台后重启；若端口被其他程序占用，按 [启动参数](#启动参数) 设置其他 `CW_PORT`，使用终端打印的实际地址 |
| 浏览器没有自动打开 | 先确认终端没有启动错误，再手动打开打印的地址；脚本入口默认不会打开浏览器，端口也与 `npm start` 不同 |

## 持续运行与自动恢复

新账号保存后默认不挂机，需用户手动开启。每张账号卡片提供 **开始挂机 / 暂停挂机**，直接控制对应账号，无须切换当前账号；已暂停托管的账号点击卡片上的 **开始挂机** 会同时恢复托管。右上角分别提供 **开始挂机 / 暂停挂机** 和 **开始托管 / 暂停托管 / 恢复托管** 两个按钮。开始挂机、开始托管和恢复托管时按已保存的间隔持续循环，直到手动暂停，不再继承旧的有限轮数。用户开启持续挂机后，自动恢复选择保存在 `data/accounts.json` 的账号 `automation.autoStart` 字段中，启动程序、重新登录和重连成功后按保存的间隔自动运行。异常中止会保留此选择，重新连接或启动程序后可恢复。旧账号沿用原来保存的启停状态，未保存启停选择的账号保持停止。

按钮左侧的 **间隔** 接受 `1–86400` 的整数秒数，修改后按账号自动保存，运行中修改后下一轮使用新间隔。挂机配置分为基地、世界、英雄、藏品、装备、日常与活动六个分类。

**暂停挂机** 会停止自动循环并关闭自动恢复，保留当前连接，控制台的手动操作继续可用。刷新网页或重启程序后仍保持挂机停止，可点击 **开始挂机** 重新运行。**暂停托管** 会结束当前任务、断开游戏连接并保存账号暂停状态，方便自行进入游戏。已连接且挂机停止时也可暂停托管。退出游戏后点击 **恢复托管**，按已保存的间隔重新开始持续循环。

希望异地登录后按时间自动接管时，在账号卡片的 **登录设置** 中开启自动重连并配置等待时间。手动生产、收成品或改种后，工具接管时会自动同步当前工厂、农田和库存，再按当前状态规划。任务由 Node 后台进程执行，可以关闭全部网页。现代 Windows CMD/Windows Terminal 的顶部固定显示控制台地址和运行提示，日志在下方滚动，调整窗口大小会重新排版。请保持启动窗口打开、电脑唤醒，关闭启动窗口或按 `Ctrl+C` 会结束进程。网络恢复后会自动续跑，重新打开网页可查看后台状态与最近 400 条日志。

## 挂机成果

进入 **挂机成果**，选择 **本次挂机 / 今日累计**，并按 **当前区服 / 同账号全部区服** 筛选。页面每 3 秒更新，展示挂机时长、实际在线时长、已确认的成功操作数、各区服成果、收获物品、消耗资源和分页明细。点击物品可展开收获来源或消耗用途。等待确认的操作单独展示；失败、跳过、计划和重复的检查不会计入成功次数。一个操作可能处理多份奖励，操作次数与物品数量分别显示。

本次普通挂机从启动到停止形成一份战报；区服轮换的多次区服访问归入同一份战报，内部交接与普通断线重连不另起战报。手动暂停轮换、修改启用计划或每日运行时段结束，会结束原战报。今日统计按北京时间 00:00–24:00 划分，跨午夜的本次战报仍保留总成果，但每日分别累计。程序退出期间不计在线时间，重启后可接续原战报；停止后仍可查看最后一次成果。

收获优先依据本工具收到的已交付奖励回包，并结合连续资产推送中已确认的数量变化；同一交付的回包与推送去重。收获和消耗分别累计，例如收到 100 个材料又使用 80 个，分别展示收获 100、消耗 80。查询得到的任务预览、初始背包和重连时的全量库存不计入收益。未提供可确认数量的结果不推测，缺少库存基线时也不会把整包资产算成收获。实际在线的挂机期间，通过该连接确认的资产变化会归入本次记录。

战报存入 `data/automation-results.json`，从功能启用时开始采集；旧日志不保证可完整回补。每份战报保留最近 2000 条明细，累计数量独立保留；已结束战报保留 30 天，运行中的战报持续保留。记录不含登录凭据，清空运行日志不会清空成果。使用 `npm run test:results` 验证统计及 HTTP 流程，`npm run test:results:browser` 验证桌面和手机页面。

## 区服轮换挂机

在 **账号 → 区服轮换挂机** 选择登录账号。若没有可配置角色，先点击 **刷新区服**。为各角色保存所需的挂机任务，再勾选参与轮换的区服，通过 **上移 / 下移** 调整顺序，并填写每区服 **1–1440 分钟**的挂机时长。勾选 **启用每日轮换** 后保存；修改已启用计划会先结束原有任务，再按新配置运行。未启用的计划只保存配置，不影响当前手动挂机。

默认时段为北京时间 **23:00–06:00**，支持跨午夜；也可选择 **全天运行**。例如三个区服分别设置 30、20、10 分钟，会按顺序循环，最后一个区服到时后回到第一个。时长从登录完成后开始计算；到每日截止时间，即使当前角色时间尚未用完，也会停止任务、取消重连并关闭连接。下次每日时段从顺序中的第一个角色开始。已暂停托管或已移除的角色会跳过；服务器明确拒绝登录等不可重试的失败，会停止该次连接，等待 30 秒后尝试下一个角色，状态与原因显示在轮换配置上方。

**意外断线自动重连**默认开启，最多重试 **3 次**、每次间隔 **10 秒**，可配置 **1–1000 次**及 **1–86400 秒**。网络波动、心跳超时或登录过程的网络错误会先结束旧任务和连接，再重试同一区服；页面显示重试倒计时与次数，等待期间读取页面不会提前登录。已开始挂机的角色保留原交接时间，重试等待也计入该角色的剩余时长；到交接时间转到下一角色，到每日截止时间停止。连续重试次数在完整完成一轮挂机后清零，避免刚连上又断线时无限重试。达到上限或关闭重连后，等待 30 秒再尝试下一角色；重试次数、等待时间和交接时间跨重启保留。手动暂停、切区、主动断开及正常轮换交接不会触发重连。异地登录顶号仍按该角色的 **登录设置**处理，轮换重连设置用于网络故障。

**暂停轮换** 会保存暂停状态并结束该账号的自动任务和连接；**继续轮换** 在时段内立即接管，在时段外等待开始时间。手动切区、连接、开始/停止挂机或暂停/恢复托管也会暂停轮换，避免调度与手动操作相互争抢。修改任务配置或查看已有状态不暂停计划。轮换运行时不改变页头当前查看的角色，各登录账号可独立配置；同一登录账号始终只连接一个区服。

关闭网页后，后台继续轮换，需保持控制台进程和电脑运行。窗口内重启继续当前角色原定剩余时间；剩余时间已结束则交接下一角色。时段外重启不会因角色原有自动挂机偏好而提前登录，轮换暂停状态也跨重启保留。各角色原有自动挂机偏好保留，关闭轮换后按原有规则管理。轮换计划与进度保存在 `data/role-rotations.json`，独立于角色的挂机配置；当前账号导出文件不包含此轮换计划。

## 资源自动更新

控制台和 CLI 持续挂机默认保持自动更新，在启动时检查资源，之后每 **30 分钟**检查一次游戏远程版本清单；版本变化才下载配置表和世界地图。自动发现旧客户端缓存时保留已知的较新分支；同分支的远程清单若低于已启用或已发现待更新的版本，会拒绝降级，也不会刷新验证时间。资源验证完整后一起启用，下一轮使用新版本重新规划。已发现新配置但下载或验证失败时，暂停使用旧资源发起新操作；旧快照保留供只读查看，已知待更新版本会保存到磁盘，重启也不会忘记。资源成功更新后解除限制；不需要保持网页或微信游戏打开。

可运行 `npm run sync-resources` 或调用 `POST /api/resources/check` 立即检查。运行日志会记录检查间隔、更新或失败结果，`GET /api/resources` 可查询发布版本、版本来源、待更新版本、最近成功验证时间、是否阻止执行及原因、下次检查时间，以及协议来源和等待重连采用新协议的连接数。仅清单检查短暂失败时，可继续使用最近验证的资源；默认超过 **24 小时**未成功验证即暂停新操作，避免长期离线一直使用旧表。`CW_RESOURCE_MAX_AGE_MINUTES` 可设置此期限（1–10080 分钟，默认 1440）；成功检查会恢复有效期，失败不会延长。首次检查失败且没有已验证快照时同样暂停执行。

默认从本机最新微信游戏包的 `resources/appConfig` 识别客户端版本，每次检查重新识别，再读取对应的远程发布清单。该包的版本缓存缺失或损坏时，会按包内已确认的官方资源地址下载版本资料。包内配置表哈希属于出厂资源，不能拿它覆盖更新的热更新清单。没有本机包时沿用已保存的目标，首次才回退 `1.14.5`；状态中标明 `last-known` 或 `fallback`，不代表已发现全局最新客户端。新版主包损坏、版本资料或新分支清单下载失败时，会保留待更新状态并停止旧资源执行。`CW_RESOURCE_APP_VERSION` 仍可显式固定分支。

**配置表和地图更新不等于协议更新。** 协议来自本机微信游戏分包、自备协议包或显式指定的 `CW_PROTO_BUNDLE`，目前没有已确认可用的协议远程下载入口。请让微信下载新版游戏包；控制台每次新连接、重连和扫码登录都会重新检查协议来源，文件变化后验证基础编解码并采用新版。已有连接保留自己的协议快照，避免在途消息混用版本。发现最新主包但协议分包尚未下载，或新版协议损坏时，拒绝新连接并提示原因，不悄悄回退旧协议。UI 图片仍可通过 `npm run sync-art -- --fetch` 按当前清单补充。

检查间隔可通过环境变量设为 1–1440 分钟，例如在 PowerShell 中改为每小时检查：

```powershell
$env:CW_RESOURCE_UPDATE_MINUTES='60'
npm start
```

`CW_RESOURCE_AUTO_UPDATE=0` 关闭自动检查与上述时效限制，按手动选择继续使用已有资源；`CW_RESOURCE_APP_VERSION` 可指定已确认兼容的客户端版本。`CW_CONFIG_PACK` 显式指定配置文件时保留其优先级，并停用远程更新和时效检查。已验证的资源版本与检查记录保存在 `work/cdn/resources/`；未验证的同步副本与微信缓存可供只读展示，不会在自动更新失败后静默代替已验证资源执行任务。`npm run sync-config` 仍可备份本地配置来源。

城战预览若仍提示缺少 `N_CityCfg`、`N_AttackCityConsumeCfg` 或某联盟主城，请先执行 `npm run sync-resources`；使用微信缓存时，先进入对应地图，再运行 `npm run sync-config` 并重启控制台。仍有异常时请保留提示中的场景、联盟编号和表名，不能用其他场景的主城或费用代替。

协议文件的统一选择顺序为：显式指定的 `CW_PROTO_BUNDLE`、本机最高版本微信包、程序根目录的 `_src_chunks_.wxapkg`、`protocol/_src_chunks_.wxapkg`、`work/extracted/_src_chunks_/src/chunks/game.js`。程序目录以源码所在位置为准，不随启动时的工作目录变化。没有微信缓存或缓存扫描权限不足时，仍可使用后面的自备文件；显式指定文件无效、最新微信包缺分包或所选协议损坏时直接报错，不尝试用旧版掩盖问题。

## 启动参数

| 启动入口 | 安装依赖 | 构建界面 | 自动打开浏览器 | 默认端口 |
| --- | --- | --- | --- | --- |
| `npm start` | 需先手动安装 | 是 | 是，可用 `CW_NO_BROWSER=1` 关闭 | `17321` |
| `.\start-console.cmd`（Windows）或 `node tools/start-console.mjs` | 检查后按需安装 | 是 | 否，手动打开终端地址 | `17323` |

两个入口都需要预先安装 Node.js 并准备协议包。脚本入口自动安装项目依赖并构建，无需再单独执行 `npm start`。若设置了 `CW_PORT`，两个入口都使用指定端口，以终端打印的地址为准。

`CW_HOST` 指定监听 IP 或主机名，默认 `127.0.0.1`；`CW_PORT` 指定端口，`CW_NO_BROWSER=1` 关闭自动打开浏览器。`CW_HOST` 不包含 `http://`、端口或路径。以下示例在可信局域网中监听所有 IPv4 接口，端口为 `17324`。

```powershell
$env:CW_HOST='0.0.0.0'
$env:CW_PORT='17324'
$env:CW_NO_BROWSER='1'
npm start
```

macOS 或其他 shell 可写为：

```sh
CW_HOST=0.0.0.0 CW_PORT=17324 CW_NO_BROWSER=1 npm start
```

监听 `0.0.0.0` 时，本机浏览器和启动提示使用 `http://127.0.0.1:17324/`，其他设备应使用这台电脑的实际局域网 IP。IPv6 地址也可用，例如 `CW_HOST=::1`；监听 `::` 时本机访问地址显示为 `http://[::1]:17324/`。

`node tools/start-console.mjs` 和 `.\start-console.cmd` 使用同一个 Node 启动入口，默认端口 `17323`，输出地址与实时日志。追加 `url` 或 `address` 只输出本机访问地址并保持窗口，不安装依赖或构建，同样遵从 `CW_HOST` 和 `CW_PORT`。追加 `status`（或 `check`）检查抓包证书和上次采集恢复记录；`recover` 恢复采集残留。这些维护命令按需安装依赖，但不构建界面或启动游戏服务。

控制台默认只监听 `127.0.0.1`。打开地址后先输入固定访问密码 **`123456`**，再进入账号和挂机界面。这是控制台密码，与游戏账号密码独立；接口、素材、账号导出和实时日志同样检查登录状态。

登录状态通过 HttpOnly Cookie 保存，12 小时内刷新无需重新输入。页头 **退出登录** 会撤销当前浏览器会话，同一会话打开的其他页面也会返回密码页；后台挂机继续运行。会话到期或服务重启后需重新登录。连续 5 次密码错误后暂停尝试 1 分钟。

固定密码适合可信环境；开放其他接口后应使用可信局域网或带鉴权的隧道，不要直接暴露到公网。直接调用 API 的脚本需先向 `POST /api/auth/login` 发送 JSON `{"password":"123456"}`，并在后续请求携带响应中的会话 Cookie。

## 添加账号与抓包

页头账号选择框展开后可查看各账号名称与连接状态，支持方向键移动、回车选择和 Esc 关闭。手机端页头的间隔、挂机、托管和日志入口保持单行；分类栏及子页签的底座与触屏按钮高度一致。自行上号前点击 **暂停托管**，工具会停止任务、断开游戏连接并保存暂停状态，刷新网页后继续保持暂停。退出游戏后点击 **恢复托管**，按已保存的间隔持续运行。

账号页为每个区服角色显示一张卡片，包含角色、区服、渠道、等级、战力、连接状态及资料更新时间。点击 **刷新区服** 可读取各登录账号已有的角色，页头选择器也逐个显示区服角色。同一登录账号只能有一个区服在线，**切换区服** 或开始其他区服挂机时会停止旧角色任务与自动重连、关闭旧连接，再登录目标角色；失败时尝试恢复原连接。各区服分别保存挂机配置、阵容、用量和运行状态，新增角色默认不挂机。合服角色同时显示原区服与当前区服。基础资料采用最近读取结果，连接状态自动刷新。更多菜单提供修改备注、导出和移除对应角色。详情中的 **连接并读取** 可获取游戏资料与资源。账号导出文件含完整登录凭据，请妥善保管。

**导出账号**：点击页面右上角的 **导出账号**，在弹窗中勾选要导出的账号，支持多选和全选。卡片更多菜单的导出入口会预先勾选该账号；未勾选账号时不能导出。选好后可使用两种方式：

- **仅账号**：保存登录凭据、备注和角色资料，不包含游戏配置。
- **账号及配置**：同时保存各账号的挂机配置、登录策略和阵容预设。导出前会等待当前页面的配置自动保存完成。

**导入账号**：点击账号页的 **导入账号**，选择本工具导出的 JSON 文件（最大 10 MB），查看新增、更新账号数和恢复配置数后确认。也支持旧版账号导出文件。按渠道和账号身份合并；重复导入更新凭据，不重复添加。仅账号文件保留本机配置，包含配置的文件替换对应账号的配置。文件中任一账号或配置不合法时整批拒绝；预览后本机账号或配置发生变化时，需要重新选择文件并确认。

导入保留本机当前账号；空账号列表沿用备份中的当前账号。导入过程不主动连接游戏或为新账号开启挂机，已有账号保持本机的托管和暂停状态，恢复的配置按正常配置更新规则生效。备份不迁移用量账本、防重记录、登录恢复状态或设备档案；导入也不会清空本机这些记录。

点击 **添加账号**，在弹窗中选择微信扫码、支付宝、益世界 APP、电脑微信或电脑抖音采集，再按当前步骤完成登录。返回渠道或关闭弹窗会清理当前流程的临时会话；电脑微信和电脑抖音采集会停止本次读取并恢复代理和证书。请求处理期间会暂时禁用返回和关闭，清理失败可留在弹窗重试。

从电脑微信或抖音采集账号时，工具会临时安装当前用户测试 CA、启用系统代理并监听登录请求，采集结束后自动还原代理并移除本次安装的证书。CA 文件和代理备份保存在项目的 `certificates/`，停止抓包并成功移除证书后会删除本次生成的文件；明确选择保留 CA 时保留。

- 抓包期间可能把正在玩的游戏顶下线，采集完成后建议重新登录。
- 未连接的账号也可在礼包兑换时自动登录，但同样可能顶号。
- 旧版本曾在项目上一级留下 `certificates/`，升级后可手动删除一次。
- 抖音单独采集可运行 `npm run capture:douyin`。

### 采集异常恢复

控制台启动时检查上次采集留下的恢复记录，并在账号页提示待恢复状态。可从 **添加账号** 选择电脑微信或电脑抖音采集，点击 **恢复上次采集残留**；也可运行 `.\start-console.cmd recover`、`node tools/start-console.mjs recover`，按记录还原本次代理改动并移除本次安装的证书。恢复结果会重新校验，失败时保留记录供后续重试。

采集恢复记录默认位于 `data/capture-session.json`，遵守 `CW_DATA_DIR`，也可用 `CW_CAPTURE_STATE` 指定文件。

### 微信扫码登录

进入 **账号 → 添加账号 → 微信扫码**，生成二维码，用手机微信核对并确认应用宝授权，再选择区服与游戏角色并保存。扫码授权与小游戏取码由当前 Node.js 进程执行，不下载第三方授权程序，不需要浏览器自动化或安装采集证书；启动控制台所需的游戏协议包仍须提前准备。

临时授权只保存在内存中，保存角色后游戏登录凭据才写入账号库。已有电脑微信账号按 openId 更新，保留备注和配置；新账号默认不挂机。二维码授权成功不代表角色已经保存，读取角色也可能使同账号的其他游戏客户端下线。

现有真实验证已覆盖扫码授权到游戏凭据交换，真实角色读取与保存仍需在控制台完成。有效期、取消清理、诊断码及完整验证范围见 [微信原生扫码登录](wechat-native-login.md)。

### 支付宝扫码登录

在 **账号 → 添加账号 → 支付宝** 添加支付宝渠道的《疯狂水世界》账号。后台使用临时无头浏览器访问玩一玩游戏页面并提取实际登录二维码。[游戏页面](https://www.wanyiwan.top/game/fkssj) 如果没找到已有浏览器，首次扫码会自动下载与当前 Playwright 版本匹配的 Chromium 到数据目录下的 `playwright-browsers`，请预留数百 MB 磁盘空间，并允许服务器访问 Playwright 浏览器下载源。已有 Edge/Chrome/Chromium 会优先复用；也可设置 `CW_BROWSER_EXECUTABLE` 指向浏览器，或设置 `PLAYWRIGHT_BROWSERS_PATH` 修改自动下载目录。服务器还需允许浏览器进程运行并能访问玩一玩与支付宝登录服务。

1. 点击 **生成二维码**，使用手机支付宝扫一扫，并在手机上确认登录。
2. 网页自动进入游戏后，控制台读取已有角色列表，展示角色名称、区服、等级和战力。只有一个角色时自动选中，有多个角色时选择要使用的角色，再点击 **保存所选角色**。合服角色同时显示原区服与当前区服，读取失败时可点击 **重新读取角色**。
3. 新账号保存后等待用户手动开始挂机，已有账号沿用保存的自动挂机选择。可前往 **挂机配置** 调整任务，再使用账号卡片或页头的 **开始挂机** 按钮开启；运行后可随时暂停。

二维码过期后可点击 **刷新二维码**，点击 **取消** 会结束本次扫码会话。读取到凭证后临时浏览器自动关闭，待保存结果在内存中保留 10 分钟。重新扫码更新已有支付宝账号时，会结束该账号的旧连接和任务，再按所选区服自己的自动挂机选择恢复。支付宝登录凭证按渠道保存一份，账号下的各区服角色分别保留；列表显示原区服、角色名称与当前区服，已有人工备注会一并显示。

扫码后的官方网页会登录游戏，可能使同账号的其他客户端下线。游戏凭证失效时，请重新扫码更新。若自动下载失败，检查服务器到浏览器下载源的网络、数据目录写入权限和磁盘空间；若浏览器下载成功但启动失败，检查系统浏览器依赖及运行权限。

### 手机号登录

控制台 **账号 → 添加账号 → 益世界 APP** 适用于益世界 APP 账号。先在游戏 APP 确认账号和角色所属区服；微信小游戏可使用微信扫码或电脑微信采集入口，抖音小游戏使用电脑抖音采集入口。APP 和小游戏角色可能属于不同渠道。

1. 选择账号密码或短信验证码登录。APP 登录统一使用已验证的益世界配置，自动完成业务和账号 SDK 初始化。首次登录或获取验证码时，工具会自动生成设备档案并保存到 `data/ewan-device.json`，后续持续复用。登录弹窗显示设备档案状态，**高级选项 · 导入设备档案** 中可查看实际保存路径或导入已有 APP 档案。
2. 使用 **账号密码** 时，填写 APP 账号或绑定手机号及 APP 登录密码，点击 **登录并读取角色**。忘记密码可在 APP 中找回，或切换到 **短信验证码**。
3. 使用 **短信验证码** 时，填写 APP 绑定的 11 位大陆手机号，点击 **获取验证码** 并确认发送，收到后填写验证码，再点击 **验证并读取角色**。同一手机号发送成功后需等待 60 秒才能重发。
4. 列表显示各角色的游戏昵称、区服、等级、战力和所属 APP 账号。短信关联多个 APP 账号时会逐个查询并展示全部已有角色，合服角色同时显示原区服与当前区服。点击要使用的角色后，选择 **保存所选角色**。部分账号读取失败时可单独重试，认证失败时需返回重新登录。
5. 页面顶部的当前账号会切换到所选账号，新账号保存后不自动挂机，点击账号卡片或页头的 **开始挂机** 才会运行。同一个 APP 账号保存为一条本地记录，再次选择其他区服会更新该记录的角色。切换已有在线账号的区服时，会等待旧角色任务退出，再按保存的自动挂机选择连接所选角色并运行。

读取角色列表需要登录游戏，可能让当前游戏客户端下线。已在线的控制台账号会复用现有连接读取列表。首次进入的 APP 账号按游戏服务端规则分配角色，查询结果为空时需要先核对游戏渠道或到 APP 中确认角色。

密码和验证码仅用于本次验证，待保存凭证在内存中保留 10 分钟。到期后页面提示重新登录。本轮修复已处理新设备缺少 SDK 初始化导致的 1068。若仍有认证错误，应核对 APP 中使用的账号信息。初始化或认证超时后可重试。

倒计时按服务器时间每秒更新。队列中尚未提供结束时间的项目显示“等待生产”，缺少成熟时间的作物显示“成熟时间未同步”。打开“建筑一览”时自动读取排产与收获状态。

## 需求联合排产

连接账号后，在 **建筑一览 → 需求联合排产** 点击 **计算联合排产**。每次计算重新读取当前订单、已开启来源的消费备料、完整库存、建筑与生产队列。计算复用 **挂机配置 → 工厂 → 需求优先级** 的保存顺序，先最小化最高级需求的齐套时间，再依次优化后续级别。同级需求共同优化工期，结果展示分层齐套时间、逐批投料和缺料、未解锁、读取失败的原因。

共享原料统一分配，已排队任务的成本视为已支付。高优先级需求沿产品配方传递到所缺的中间材料与种子，需求获得库存或在途覆盖后重新计算继承级别。共用生产位与原料的任务遵守占用约束，独立生产位可以同时开工。高优先级任务等料时，共用设备可插入能够在其开工前完成的低级任务。整体方案以高级齐套时间优先，随后比较低级齐套时间。

建筑备料同时遵守来源选择、**缺料时为建筑备料** 开关、首建或升级开关、前置建筑、等级人口与禁用设置。已齐的建筑材料在方案中独占保留。常规备货水位按库存策略处理。当前订单中未列入优先级列表的来源在最后一级计算。用户开启的博物馆、海兽等消费备料使用相应来源的级别，材料备齐后独占保留。

开启工厂的“按需优先生产”并将“海兽进阶”放在需求列表首位后，同一轮的进阶投喂会先于博物馆和培育队列喂养使用共用材料。多只海兽需要同一种材料时，每只按本轮剩余库存检查。执行预览会列出每种缺料的需求、库存、可用数量，以及已安排或设置保留的数量。

已建成的普通工厂升级时可继续按当前等级生产。每厂最多排六件，默认同时加工一件，有效普通月卡可同时加工两件。挂机按需求优先级选好本批产品后，如果调整同级需求产品的先后能让整批更早做完，就按双位工期调整下单顺序。排程预览按各自在产任务的服务器完工时间释放生产位，月卡临近到期时，仅将预计可在到期前完成的新任务计入第二位。

农田按单批产量合并需求，自定义种植遵守作物清单和开工水位。新增任务遵守当前生产开关、配方等级、仓容、活动窗口和订单截止时间。本人已占用的联盟商船船舱已有提交材料证据。

计算采用固定快照、当前设施等级和确定的在产收益。齐套后的已启用订单按立即提交释放库存估算，关闭提交的订单独占相应材料。生产、收获与提交采用零操作延迟，其他消费与备货任务需让出相应原料和产能。外部采集、购买、广告和道具加速、未来升级收益需在新快照中确认后重新计算。

“按配置优先级的模型内最优”表示在页面列出的约束与耗时下，已经证明逐级最优。后续层的最优值以更高级需求已优先满足为条件。配置公式推算的耗时会标为估算，会话内观察到的同厂同产物耗时标为实测。搜索达到预算时展示当前可行方案和下界，缺失必要状态或原生自动生产持续追加任务时显示待确认。联盟招募的刷新时间作为重新核验边界，预计齐套越过该时刻时显示需求待确认。计算结果通过只读接口生成，可作为调整生产顺序的依据。

商人订单、贸易港和居民订单的材料会参与预留。商人订单未齐时可以交付已备齐的居民单，再安排补产；商人订单齐备后按其提交开关处理。联盟募兵默认关闭，可在“挂机配置 → 世界 → 联盟 · 募兵与互助”开启总开关及“自动在联盟城市募兵”。每轮最多募兵一次，只使用扣除其他订单预留后的现有材料；需要补产时另开“联盟 · 募兵与互助 → 募兵缺料自动备料”，达到游戏或用户每日上限后停止为下一单备料。新旧海面、港口、基地和锻造流程共用材料与金币扣款检查，手动居民交单同样受保护：先核实订单、养成进度或队列等业务结果，再读取完整库存结算，补产或金币收入不再因余额高于历史扣款阈值而卡住。未知操作保留相关材料，其他材料可继续使用；同一进程内重新连接会继续核对，不按超时直接清空记录。装备锻造若产物由游戏内其他入口处理，装备锻造预览会显示“确认已处理并解除”，只允许在工厂空闲且用户明确确认后清理旧记录，不退回已确认消耗。

**工厂开关的区别：** “按需求调整游戏自动生产目标”只控制游戏内已开启的原生自动目标；普通排产由“自动生产”和“按需优先生产”控制。关闭“按需优先生产”后，普通排产按备货水位从短到长补库存；联盟募兵、红船的独立备料开关仍各自生效。协议每条请求只能安排一件，工具会按本次空位串行安排一批（当前游戏配置最多 6 格），不会超过空位或跳过库存核对反复下单。批次遇到拒绝、暂停或断线时停止后续下单，可能已发送的部分继续保留核对记录。

**工厂自动接续：** 挂机期间优先按服务器返回的最早完工时间安排收取与补产，建筑状态推送可提前唤醒，不必等到下一主挂机轮。尚未开工的排队项可能没有完成时间，不会按配方耗时猜测剩余时间。“挂机配置 → 工厂 → 兜底检查间隔”可设 1–300 秒，默认 30 秒，用于没有可靠时间、缺料、满仓或检查失败时复查；已知时间仍优先处理。完成与状态变化检查合并处理，最短间隔 1 秒，防止忙轮询。主轮在业务完成后的安全位置检查工厂，所有请求仍按账号串行；当前业务或网络请求尚未完成时会顺延，不保证零延迟。停止挂机或断线后，接续检查一同停止；命令行循环同样支持接续。

农田播种发送前复查空地，等待业务回包后再核对地块作物与完整库存，避免补货掩盖种子扣减而一直等待。结果未知时只保留相关种子和地块，不阻止其他材料的操作；后续读取继续确认，不因超时或重连直接重复播种。日志会区分“已确认”和“等待确认”。

博物馆探宝发送前复查地图、英雄占用和材料需求，派遣后先核对服务器队伍或已领取的关卡进度，再读取完整库存。工厂补产使库存持平或增加时，也能确认旧扣款并恢复贸易港装货；丢回包或重连后会继续核对。尚未确认的探宝仅保留相关材料、地图与英雄，不阻止贸易港使用其他材料，单凭超时或库存下降不会重复派遣。

详细锻造随每轮挂机检查，检查频率跟随页头的挂机间隔；按“自动领取完工装备”和“自动续产”分别执行，在领取确认后续产，达到下单上限仍可领取。工具按服务器当前批次接续游戏内加速、领取和换配方后的任务，已确认开工的消耗继续计入预算。游戏内原生自动锻造开启期间，工具不领取、续产或分解。暂停托管或顶号后重新登录时，会同步装备厂、装备、材料和金币。旧未知请求归档并保留预算，当前工厂按新状态安排。同步读取失败时等待后续连接重试，普通网络重连继续核对原请求。

开启“使用游戏原生自动锻造”后，挂机会为所选工厂同步游戏原生开关并回读确认；需要游戏的装备工厂自动锻造月卡权益，不会购买权益。此模式下由游戏自己的逻辑运行，工具的领取、续产、分解、配方、材料保留和预算都不生效，周活动的品质顺序和积分停止规则也不限制游戏原生，原设置仍保留。关闭此项后，工具会先关闭由本工具开启的原生开关，再按工具配置继续；不会关闭原先在游戏内开启的开关。暂停总开关或停止挂机不会关闭游戏内的原生自动，如需停掉原生自动，请关闭此项并运行到确认关闭后再停止。

装备分解与海兽放生会随对应模块每轮扫描库存，只处理所选品质中闲置、未养成的对象。蓝紫橙海兽的天然高星可参与放生，已升星的红色海兽会保留。玩家手动处理后，托管恢复时会重新读取库存与占用，核销已消失的 UID，并在复核通过后继续处理在场对象。工具无法读取游戏客户端保存在本地的锁定标记。

### 指定英雄养成

**杂项 → 英雄与装备 → 英雄任命** 提供自动委任开关，默认关闭，开启后随挂机按游戏规则分配英雄。委任优先级支持拖拽和上下移动，越靠上越优先，顺序按账号自动保存。默认顺序为生产时间减少、训练营产量提高、贸易时间减少、建造速度提高、种田时间减少、海兽培育速度提高、锻造时间减少。

在 **挂机配置 → 英雄 → 英雄养成** 中选择当前账号要培养的英雄，再勾选动作。名单为空就暂停培养，不影响已开启的技能展示领奖。旧配置中名单为空曾表示培养全部英雄，升级后需要重新选择。

- **升级、升星和技能升级** 分别启停。在“高级设置”中可设目标等级、目标星级、保留英雄经验，以及英雄升星时是否可用万能碎片。
- **技能进阶、专武升级和专武升星** 按英雄和赛季开放条件执行。开启专武升级后，符合条件时可从未铸造升至 1 级。专武升星消耗本体碎片和对应品质的升星材料。
- **领取技能展示奖励** 处理所有已拥有、配置有展示奖励且尚未领取的英雄，不受指定英雄名单限制，通过回读已领记录确认结果。

在 **挂机配置 → 装备 → 装备自动锻造** 中选择工厂并开启总开关，再选择“自动领取完工装备”和“自动续产”。只领取时可关闭续产，无需选择配方；续产时才按配方、材料保留、金币保留和每日预算执行。保存配置后需要运行挂机，预览本身不执行动作；表中的“游戏原生开关：关闭”仅表示游戏内的开关关闭，不表示工具自动领取关闭。切换原生模式后按上文的游戏逻辑运行。“装备制造原有规则”及其两个旧开关已停用，旧配置导入不会另行启动制造。

在 **挂机配置 → 藏品** 中设置藏品激活、升星、大师等级和套装升级。藏品招募和累计招募奖励也在此分类中，英雄的招募开关在 **挂机配置 → 英雄 → 英雄招募**。

英雄养成的配置与只读计划预览统一在 **挂机配置 → 英雄** 中查看，开启后随挂机执行。

### 保存阵容与临时切换

进入 **阵容 → 我的阵容**，点击“保存游戏当前阵容”可读取并命名保存当前搭配，点击“新建阵容”或已有阵容的“编辑”打开布阵弹窗。列表中的“查看”打开只读详情，展示已保存的英雄站位、阵型及海兽信息，未连接游戏时也可查看。同页的“推荐阵容”提供游戏攻略中的搭配。

- 选择英雄后点选站位，或将英雄拖到站位上。拖动已上阵英雄可移动或交换位置，也可使用“下阵”。英雄列表支持名称、阵营与职业筛选。
- 阵型列表按当前游戏配置展示，解锁状态来自角色数据。选择阵型后按新阵型站位重新安排已有英雄，上阵人数遵守当前主线进度。海兽按品质、星级与等级展示，保存精确编号。
- 名称、英雄、站位、阵型和海兽保存在当前账号的预设中。点击“保存阵容”提交本地配置并关闭弹窗，保存失败时保留输入。关闭按钮与 Esc 会保留当前网页内的未提交草稿，切换账号会关闭弹窗，返回原账号后可继续编辑。
- 在 **挑战** 页为主线和各试炼选择本次使用的阵容，旁边的“查看”可核对已保存的搭配。默认选项为“使用游戏当前阵容”。单次试炼与连续挑战都使用点击开始时选定的预设，后续场次会重新读取该预设的最新内容。
- 在 **挂机配置 → 推关与试炼** 的自动主线及各副本项目中选择保存的自定义阵容，修改后自动保存。每项均提供查看入口。通过顶部导航的 **阵容** 页管理自定义阵容。

查看使用本地配置显示英雄与阵型，海兽有已读取的详情时显示名称，只有保存编号时显示完整海兽 UID。查看内容来自已保存的阵容，尚未提交的编辑草稿可通过“编辑”继续处理。

每场挑战先记录游戏当时的阵容，核对所选英雄、阵型和海兽，再切换并回读确认。战报确认后恢复原搭配，再回读确认恢复成功。手动停止会等待在途战报与阵容恢复，暂停托管和正常关闭也会等待这一步完成。主线、普通试炼与竞技场防守共用游戏阵容模块，因此临时切换期间会影响该模块的站位。

连接中断或进程异常退出时，恢复信息保存在 `data/lineup-runtime.json`。下次连接会先核对角色、区服和游戏当前阵容。若当前仍是临时挑战阵容，自动恢复原搭配。若已变成第三套阵容，“我的阵容”会展示原阵容与挑战阵容摘要，可重新核对、恢复原阵容或保留当前阵容。恢复完成后允许执行排队任务。因恢复失败而停止的连续挑战需要重新开始，对应挂机挑战需要重新开始托管，页面会显示处理状态。

阵容预设及自动绑定随游戏配置导入、导出，恢复记录独立持久保存。删除预设会同时清除引用它的自动绑定。CLI 的 `loop` 与 `stages` 写入模式也使用保存的对应绑定，`stages --dry` 保持预览行为。

布阵素材通过 `npm run sync-art` 从本地游戏缓存建立索引，缓存缺图时可使用 `npm run sync-art -- --fetch`。当前使用游戏头像展示英雄，布阵背景和阵型图标来自原素材。切换与恢复已通过隔离假客户端、协议编解码及浏览器回归，真实账号写入尚待验证。

### 世界与挑战

海盗相关设置统一在 **挂机配置 → 世界 → 海盗讨伐**。“每日免费扫荡”和“自动讨伐首杀”分别控制，可同时开启；合并入口后保留原有开关和参数，执行方式及消耗不变。

**总览 → 资源田概览** 的工厂、绿洲、油罐卡片分别显示占地数量和有效基础时产。点「查看明细」可查看该类已占田的城市、等级和有效时产，点行末的「放弃」可核对格号并确认。点「占领」或「换田」可查看当前类型的全部候选田，可直接占领或点「替换」选择已有地块。各表均按等级从高到低排列。**挂机配置 → 世界 → 资源田** 可按相对比例或固定配额设定三类田的目标数量。开启自动占领后，每轮最多派一队，优先选高级田，同类高级田可占时会替换低级田。若要在失地后重新占田，开启「失地后自动补齐」。换田先放弃旧田，新田出征或战斗失败会损失原田的产出。[资源田玩法与策略](resource-fields.md)

**城战攻守目标**

进入 **挂机配置 → 世界 → 联盟城战**，选择参与舰队并逐队设置职责。进攻和防守分别配置目标来源、城市名单和优先策略。以一队攻 A 城、二队守 B 城为例。

1. 将一队设为进攻、二队设为防守。
2. 将“进攻目标来源”设为“只选择指定城市”，在“指定进攻城市”中选择 A 城。
3. 将“防守目标来源”设为“只选择指定城市”，在“指定防守城市”中选择 B 城。
4. 如需立即由工具按此配置接管，将原生委任次数设为 **0**。保存完成后，可先选择“联盟/城战”只读预览，核对两队目标。

两侧也可分别使用自动和指定模式，例如进攻跟随联盟有效目标、防守固定 B 城。每侧在自己允许的目标范围内按队数与距离，或按集结／指定城市顺序选城。进攻目标须为本盟已宣战的敌城，防守目标须为正在受宣战且仍属本盟的城市。该侧没有有效目标时等待。

升级时保留已设置的舰队职责。缺少独立防守目标字段的旧配置会把原共享目标设置复制到防守侧，之后两侧可分别修改。配置导入采用相同迁移规则。

城战的攻守分工和目标配置在工具接管后生效，原生委任跟随联盟集结。工具使用舰队已保存的英雄编队，在服务器城战时段处理有效攻防目标，并跳过舰队当前所在城市。发送前重新核对宣战、归属、职责和该侧目标配置，城市失守或宣战结束就取消旧计划。最后一次读取与服务端实际处理之间仍可能发生城市归属变化。

汽油统一按实际可用库存检查，不再提供保留量、每日/本次预算或单次维修费用上限。旧配置中的这些字段在读取、导入和保存时自动清理；消费用量、待确认占用、舰队锁和防重复派遣继续保留。

原生委任次数设为 0 或 N 且达到接管条件时，工具会关闭所选舰队的原生委任开关，确认关闭后才按工具设置出战。接管后的进攻和防守都没有每日派遣次数上限。防守队列直接使用服务器计数，不保证排除城防 NPC；正在交战的舰队只统计对应一侧的本盟非 NPC。维修与付费行军按实际汽油库存扣除待确认消费后检查；免费驻防不消耗汽油，仍检查耐久与舰队占用。战后维修请求本身仅花汽油。要花钻石加速维修，请在对应舰队的设置中开启“允许维修加速”并设置每日钻石上限。短维修会监听推送并追加最多三次只读复查，后续确认时补发日志；不能仅凭舰队空闲就把未知任务记成成功。

**自动推关设置：** 在 **挂机 → 世界 → 推关与试炼 → 配置** 中开启主线/闯关或试炼，选择副本，自动保存完成后点击页头的 **开始挂机**，账号暂停托管时点击 **恢复托管**。海盗首杀在 **挂机配置 → 世界 → 海盗讨伐** 中开启“自动讨伐首杀”，并设置舰队与目标。主线、每个试炼分别记录同一关的连续战败，海盗记录连续战败；成功通关或首杀后对应计数清零。**失败停止次数**默认 3，可设 1–100，不是挑战总次数。达到上限后本次挂机不再挑战对应玩法，其他任务继续；跨轮次与断线重连保留计数及海盗汽油用量，暂停后重新开始挂机会重置本次计数。未确认的海盗派遣仍由持久记录拦截，不会因重启而重发。

**手动挑战：** 在 **挑战** 页手动开始/停止主线、试炼和海盗首杀推进；试炼保留“挑战一次”。本页失败停止次数独立于挂机配置，主线/试炼默认 3 次，海盗手动推进默认 1 次；操作不会开启挂机。主线与试炼共用至少 5 秒的挑战发送间隔，避免同轮切换玩法触发服务器限频。服务器明确拒绝不算战败，自动任务下轮再检查；战报超时或结果不明仍停止重发。

### 联盟城战逐队加速

“挂机配置 → 世界 → 联盟城战”直接展示参与舰队、维修与派遣限制。全局攻守策略位于这些设置下方，默认收起。点击“城战参与舰队”旁的“展开设置”显示舰队职责，再通过每队的“展开设置”调整独立策略和加速参数。下级参数默认收起，打开功能开关不会自动展开；配置错误会自动展开对应设置。模式或开关切换后作废旧草稿的校验提示，下一次保存按当前配置重新校验；改回已保存值会立即清除过期提示，不再要求填写前一模式的条件项。攻守两侧分别支持联盟有效目标／指定城市，以及队数与距离／原有顺序。原生委任次数设为0时由工具立即接管，否则目标策略在原生额度用尽后生效。

世界配置与挂机世界入口先显示联盟城战、万吨巨轮、硅矿；实际派遣顺序仍使用“舰队调度”中已保存的顺序。调度列表包含“硅矿采集”，可用鼠标或触屏拖动行首手柄，松开后自动保存；也可使用上移／下移按钮。拖拽取消不改变原顺序。已出征舰队不抢占，有效城战时段的预留仍优先。舰队名单来自当前账号服务器状态：只有两支就只显示两支；未同步时提示连接后重新载入，不用配置表猜测第三支。历史未解锁队伍设置保留，解锁后恢复显示，不会因为编辑其他项目丢失设置。

每队的“允许维修加速”和“允许派遣加速”默认关闭，可以分别开启。付费加速还需开启“城战接续总开关”和 **基础 → 加速与钻石** 中的“自动钻石消耗总开关”。逐队设置会显示未生效的开关或零预算，并提供修改入口。只处理城战参与名单中勾选的舰队及类型；行军目标必须是城战城市，不加速返航、巨轮或硅矿行军。维修可包含手动开始的现有维修，但其他玩法已确认发起的维修由各自设置负责。

- 每队维修与派遣分别设置开关、剩余秒数和各自每日钻石上限，不再设置单次维修或整段航程钻石上限。各项每日上限默认0，0禁止消费。
- 每队的“维修智能省钻”“派遣智能省钻”分别位于对应加速选项内，开关和最多等待秒数各自独立。两项省钻默认开启，最多等待默认5秒（可设1–60秒）；加速本身仍需另行开启并设置预算。例如舰队1可以关闭维修省钻、保留派遣省钻，舰队2保持维修省钻。旧共用配置兼容迁移，已有显式的新设置优先。
- 维修按剩余分钟向上取整，在2:01这类临界点等到1:59，基础档可省10钻，实际取决于当天阶梯费率。同一次维修或整段航程最多只短等一次，截止时间固定，复查、推送和重连不会延长等待，也不会跨完一个分钟边界再继续等下一分钟。
- 关闭某一项智能省钻后，该项不再主动短等；只要剩余时间超过目标且预算足够就加速。关闭派遣省钻还会忽略“每次至少节省多少秒”的额外门槛，不影响维修设置；派遣省钻开启时，预计节省不足门槛（默认30秒）就不花钻，即将自然达到目标时短等。
- 行军每次速度翻倍，费用读取“行军加速消耗”。每轮每队至多一次，读回确认后若仍超过目标，安排1秒后复查；剩余时间小于等于目标即停止，整段航程费用累计，不会每轮重置。维修加速确认补满后，同轮刷新维修占用并检查城战派遣，不额外等待常规城战检查间隔；实际执行仍受串行任务及网络耗时影响。
- 钻石维修一次完成所有剩余维修，无法精确加速到指定秒数；维修阈值表示“剩余这么多秒以内不再花钻”。按当天累计分钟阶梯计价，累计值缺失时按最高档保守预留，费用无法核实时不发请求。
- 维修累计档位由全角色共享，城战和硅矿的维修加速都会计入。发送前先计入本地累计分钟，防止推送迟到让第二队沿用旧低价；未知维修加速按最高档预留，明确拒绝才撤销。2:01等到1:59当前可省10–20钻，取决于所处档位，并非始终10钻。
- 每队维修和派遣的每日用量独立计数，另需满足全局钻石总开关／日上限／保留量；不再设置城战加速合计日上限，旧配置中的该字段自动清理。结果未知跨重启、跨日继续占用预算，自然到期不算加速成功；已确认加速但钻石余额尚未同步时暂缓下一次花钻。巨轮、硅矿原有加速仍由各自配置管理，也计入全局钻石预算。
- 联盟城战的只读预览包括加速计划、费用和等待原因；保存不自动开始挂机。

行军先执行必要的加速，在最后接近目标时短等即可，不必提前在二倍、四倍时间边界等待。核对依据、计费示例和协议限制见[智能省钻协议分析](fleet-speed-protocol.md)。

### 军备竞赛

在 **挂机配置 → 日常与活动 → 军备竞赛** 设置自动参与和达标领奖。默认关闭；开启总开关和所需分项后，挂机按服务器当前主题全天参与，修改后自动保存。通常周一种田、周二海兽、周三藏品、周四订单、周五装备、周六城战、周日英雄。周六沿用 **世界 → 联盟城战** 的已有配置，本页不主动开启城战。

**执行预览上方的军备竞赛排行** 显示服务器当前主题、本人名次与积分、榜单、结算时间和更新时间。进入该页会读取一次，可点击“刷新榜单”重新读取；30秒内返回页签使用缓存。只展示服务器返回的名次，本人未出现在榜单时明确提示，分组中或已结算时不沿用旧榜。排行独立于自动参与开关，查看不会启动挂机、连接未连接的游戏账号或执行领奖消费；切换账号会清除上一账号的数据。

军备竞赛与普通自动化独立：普通任务始终按自身开关执行，活动主题不匹配、积分达标或活动读取失败都不会关掉普通任务。每轮优先执行当天军备竞赛，普通任务随后重新读取当前状态；两条路径共用材料、预算和待确认记录，避免重复消费同一批次。活动沿用已选物种、品质、配方、英雄及目标，空选择时提示等待，基础配置不会被改写。货船、工厂加速等额外能力仍需原有授权。保存配置本身不会开始挂机。

例如，普通装备自动锻造关闭但军备竞赛装备打造开启时，打造日仍会按已选工厂和配方领取、制造；非打造日等待。普通自动锻造开启时，每天按普通设置运行，活动达到积分目标后普通制造仍可继续。装备预览同时核对两条路径，说明当前由哪套规则安排动作。游戏原生自动锻造由游戏处理，不受周活动限制。

| 三类试炼广告扫荡 | 各 1 | 先完成首轮免费扫荡 |
| 广告商店 | 按商品 | 逐商品读取服务器上限 |
| 走江助力、龙王罗盘广告礼包 | 各 1 | 活动开放时领取 |
| 工厂生产广告加速 | 3 | 每次 30 分钟，优先剩余时间最长的已开工队列，不会为此新开生产 |
| 建筑升级、博物馆展柜广告加速 | 共 3 | 每次 30 分钟，只加速进行中的目标；展柜到期后自动提交完工 |

有免广告权益（VIP 特权或首充记录）的账号与游戏内流程一致，立即领取。

**已开启的广告任务默认也为无免广告权益账号领取。** 不再单独提供无权益开关，旧配置中的关闭值也不再阻止领取。工具提交广告申请，不播放视频，等待设定秒数后直接领奖；有权益时立即领取。这不是游戏客户端的正常流程，服务器可能识别，存在账号处罚风险，需自行评估。等待秒数默认 15，可设 5–120。现有测试记录中，15 秒在 7 个入口成功；5 秒只在藏品招募成功；广告商店 3 秒被拒。试炼扫荡、建筑加速和博物馆加速尚无真实账号验证记录。

无权益模式下，等待期间账号操作队列会被占用，所以整轮挂机每轮最多处理 1 次（挂机收益除外），手动试炼扫荡和手动走江助力不受此限。等待中暂停或断线时不发送领奖；服务器返回“广告未完成”时跳过该入口并冷却 5 分钟；结果未知时保留记录，核对次数后才继续，不重复提交。

### 总览、地图与工具

- **运行概览**：按功能分组显示当前进度和条件，可搜索、筛选异常/受限项。分组展开时保持单列顺序，不改变其他分组位置。角色区服显示游戏内名称（如“海岛1986服”）和 worldId，账号列表与区服列表同样显示名称。
- **世界地图**显示城市、货轮和舰队，支持拖动、Ctrl+滚轮缩放、图层过滤和定位舰队。地图默认每 10 秒刷新，可单独调整为 5–300 秒。行军位置按已同步的起终点和时间推算。
- 舰队表的「操作」列随当前任务显示「派遣加速」或「维修加速」。点击可查看本次完成所需的最高钻石费用。确认一次后，工具会逐次加速同一航程直到抵达，或一次完成当前维修。执行结果显示在舰队表下方。
- 点击城池可查看所属联盟、攻守队列和可用操作。电脑端在城池旁显示详情，手机端打开弹窗。舰队选单显示本账号各队的状态，默认选中第一支可派舰队，忙碌或已预留的队伍显示为灰色。选好舰队后，点「前往」可免费调往本盟城市。城战时段可点「进攻」前往本盟已宣战的城池，行军汽油按游戏规则扣除。
- 符合 VIP 条件的成员在本盟非主城可点「高级募兵」。确认框显示本人的募兵令库存、消耗和新增守军数。当前游戏配置为 VIP10 起，消耗 1 枚联盟募兵令增加 10 名守军。
- 盟主和副盟主可对符合条件的目标「宣战」，也可在本盟已宣战或正在受攻的非主城点「集结」。切换集结城会改变游戏内城战委任跟随的目标，手动派遣的舰队仍需单独选择。
- 本盟有多个进攻目标时，盟主和副盟主可「取消宣战」。费用从操作角色的个人钻石扣除，确认框显示当前报价。募兵或取消宣战显示结果待确认时，点对应的「核对」按钮可检查游戏状态，无需再次提交消费。
- **礼包兑换**：顶部勾选一个或多个账号并开始兑换，已暂停账号不可手动兑换。下方共享码库仅通过“批量新增”维护，每行一个码，单次最多 500 条，可设置共用到期日；所有条目校验通过后一起保存，未添加账号也可维护。公共码库在控制台运行期间每分钟检查，每天北京时间 08:00 后同步，当天成功后使用缓存；首次无缓存且无法联网时保留内置码表。每个账号的自动兑换默认关闭，开启后按可用码库兑换，未连接账号会自动登录，可能将游戏客户端顶下线；暂停托管后停止继续发送，恢复后可在后续检查继续。账号各自排队，兑换请求跨账号逐个发送；成功、已用或结果未知的码不重发，限频停止同批余码。底部兑换记录支持账号切换、状态筛选、每页 10/20/50/100 条和导出当前账号、当前筛选下的全部 CSV 记录；仅部分明确拒绝的结果允许人工重试，包括限频和尚未到兑换时间。
- **掉线处理**：心跳独立于业务操作，每次允许 10 秒应答，连续 3 次无应答才断线。挂机中的心跳超时、普通网络中断或消息重传失败会按 3、6、12、24、48、60 秒（上限 60 秒）退避重连，成功后继续原进度和持续循环。旧轮次退出后才恢复，不清除未知操作的预算或材料预留。网页会显示网络恢复状态，CMD 记录重连次数和结果。
- **异地登录恢复**的自动重连默认关闭。在账号卡片的 **登录设置** 中开启后，被顶号的账号会按已配置的常规间隔、深夜时间段与间隔、随机抖动和重试上限自动恢复连接，并先同步当前工厂、农田与库存。原有挂机继续运行，未运行挂机的账号恢复连接后保持挂机停止状态。等待时间和已尝试次数按账号持久保存，重启控制台后接续等待。等待期间保存登录设置会立即重算下一次重试时间，网页刷新和只读查询遵守这次等待。手动暂停托管、停止挂机或断开连接会取消自动重试，关闭自动重连开关、凭证失效、协议错误或耗尽重试次数也会结束重试。手动暂停托管后仍需自行恢复托管。
- **日志与手动入口**的中文业务日志同时输出到网页与 CMD，关闭网页后仍输出轮次、动作和停止原因。网页默认汇总全部账号，分类 Tag 按系统灰色、基地与资源绿色、世界与联盟蓝色、日常与活动紫色显示及计数；每条日志附账号名称和功能 Tag，警告/错误用黄/红 Tag。内部 ID 仅在账号标签悬停提示中保留，同名账号用序号区分。分类与账号各占一排带计数的 Tag，选中样式统一；每排始终单行显示，超出宽度可左右滑动，长账号名单行省略；点击或键盘切换时选中标签自动进入可见区域，实时日志更新不会重置滑动位置。点击日志中的账号 Tag 也可直接筛选。终端每行同时显示时间、账号名称、中文功能类型和等级，例如 `[12:30:00] [生产主账号] [生产] [信息] 工厂完成木板生产`。可组合筛选账号、分类及警告/错误，账号 Tag 仅提供“全部”和实际账号，不再保留重复的功能下拉框。筛选独立于页头账号，切号不会清空记录；选定具体账号后可通过筛选栏同排的“清空”按钮清空该账号的全部运行日志（不限当前分类），其他账号和系统日志保留。全账号订阅重新打开会回放合并后的最近400条记录，多窗口和断线重连同步各账号的清空水位。建筑一览支持逐张提交或刷新居民订单。英雄装备/阵容、联盟及活动单次操作也继续可用。同一账号与挂机串行执行，发送前复查条件。原始协议日志 `data/protocol.log` 按 5 MB 轮转到 `data/protocol.log.1`，可用 `CW_PROTOCOL_LOG_MAX_BYTES` 调整上限。`CW_DEBUG=1` 才额外向终端输出原始协议。

顶部固定区仅用于支持 VT 的交互终端，启动地址通过 OSC 8 高亮为超链接，支持该协议的终端可直接点击；窄窗口中分行显示的地址仍指向完整 URL。重定向到文件、`TERM=dumb`、不支持的终端或过小窗口自动使用普通文本。设置 `CW_PIN_HEADER=0` 可关闭固定区和链接输出。终端输出分批处理，积压超过缓冲上限时会提示省略较早记录，网页日志仍按原规则保留。Windows 旧控制台选中文字可能暂停程序；长时间挂机时避免保持文本选择状态。电脑休眠期间无法发送心跳，唤醒后的普通网络断线会进入上述恢复流程。

### 问题反馈日志

协议解码失败时，网页和终端保留具体消息名称，例如“当前协议无法识别消息：SCNewFarmUpdate”（示例名称）。同时在 `data/protocol-errors/` 保存独立的 `.json` 错误快照，记录消息名、序号、当时等待的请求、近期收发报文头和失败收到帧的十六进制内容。原始帧最多保留 256 KiB，超限会标记截断；快照最多保留 100 份，超过后清理最早的快照。登录阶段及认证类报文不记录原始内容；畸形帧没有有效报文头、无法排除认证内容时，也会省略原始内容并记录原因。普通 `protocol.log` 轮转不会覆盖这些快照；设置了 `CW_DATA_DIR` 时，快照位于该目录的 `protocol-errors/` 子目录。

工厂、农田、海兽或其他功能开启后没有动作时，先看日志中的结果：**“已跳过”“等待确认”“材料扣款尚未确认”都不表示执行成功**，“信息”只是日志等级。材料扣款待确认表示之前的操作尚缺完整核对证据。自己进入游戏后继续生产、领取成品或改种，会改变工厂队列、待收成品和地块，可能使旧操作无法再由这些状态确认；回包或库存同步失败也可能造成等待，不能仅凭这一行日志认定具体原因。

主动暂停后的操作流程为 **暂停托管 → 进入游戏操作 → 退出游戏 → 恢复托管**，恢复时按已保存的间隔持续运行。希望异常顶号后自动接管时，请在账号卡片的登录设置中开启自动重连，工具会按已配置的时间等待恢复。工具接管时会自动读取完整工厂、农田和库存，归档已无法核对的旧普通排产、播种占用，并按当前状态重新规划。已开启的顶号自动重连，以及“连接”“开始挂机”“恢复托管”“开始托管”入口，都先完成这次同步。旧操作保留为未知，预算以及海兽、钻石或其他玩法的待确认记录继续保留。读取失败时保留旧记录并暂缓写入。自动重连和运行中的挂机会按相应重连策略重试同步，其他情况下由后续页面读取或正常开始挂机重试。同步期间界面显示“正在同步生产状态”。

遇到异常请先保留日志，不要先删除 `data/` 或重装。更新并重启后若仍能复现，请在复现后及时复制日志，避免后续轮转覆盖；请使用 [问题反馈表单](https://github.com/xutongxue233/crazywaterworld/issues/new?template=bug_report.yml)。已有对应 issue 时直接补充到原帖，附上：

- `protocol.log` 和 `protocol.log.1`（存在时），可压缩成 ZIP 上传。默认位于项目 `data/`；设置了 `CW_DATA_DIR` 时到该目录查找。请提供问题发生前后的一段完整日志，截图可作为补充。
- 出现“服务器消息解码失败”时，附上 `protocol-errors/` 中对应时间的 JSON 快照；即使普通协议日志已轮转，也请保留这份快照。
- 发生的北京时间、复现步骤、预期行为和游戏内实际结果；说明是否在手机/电脑游戏客户端登录同一账号，是否先暂停托管，手动进行了生产、收成品或改种，以及自动重连或恢复托管后的同步结果。
- 当前版本（可运行 `git rev-parse --short HEAD`）、启动方式、Node.js 版本（`node -v`）以及相关挂机开关和详细配置截图。工厂/农田写明建筑和产品，海兽写明驻扎建筑和目标，舰队问题写明编号。

协议日志中的登录凭据在写入前脱敏。**只上传上述日志和必要截图，不要上传整个 `data/`、`accounts.json`、账号导出文件或登录凭据。** 若无法取得日志，请说明原因；这些信息用于区分配置条件、未知操作保护、顶号和程序错误。

## 配置与预算

读取旧配置时先按版本转换历史字段、补齐新增项并校验，执行使用转换后的设置，各账号独立迁移。已有有效开关、阈值和预算保留，新功能不会自动打开。以后调整字段含义需要明确的版本迁移，不能仅修改默认值来覆盖用户选择。配置格式编号高于当前格式时，也先尝试按实际内容兼容；校验通过且原有字段和值能够完整保留，即可正常读取、保存和挂机，保存不会降低已有版本号或丢弃账号元数据。确实存在不兼容字段、非法值或会被当前规则丢弃、改变的设置时，显示具体路径和原因并保留原文件，不自动重置为默认配置。

文件的 `version` 和账号的 `settingsVersion` 是配置格式编号，不随保存次数增长。账号的 `revision` 是用于检测多页面保存冲突的修订号，每次成功保存增加 1；它可以远大于格式编号，不代表配置来自更新版本。

已配置账号的 `data/automation-settings.json` 或对应账号配置被删除、损坏时，控制台会停止挂机并关闭自动启动，恢复全部关闭的默认配置并提示重新配置。损坏原文件会先备份为同目录的 `.corrupt-*.bak`；正常账号配置、登录凭据与消费账本不会重置。运行中的配置变化也会被检查，旧页面草稿不会自动覆盖恢复结果。重新载入、配置并保存后，需要手动开始挂机。无法读取或内容不兼容的文件只报错并停止执行，不擅自覆盖；较高格式版本仍按上述兼容规则判断。首次添加账号尚未保存配置不算损坏，正常升级继续执行配置迁移。

后台更新或重启后，旧网页会提示刷新并暂停自动保存。页面加载时固定的版本随请求发送，后台拒绝过期页面或未携带版本的旧网页写入。未保存草稿保留在原页面，可先下载游戏配置草稿或复制其他修改，再刷新；停止挂机和断开连接仍可用。配置修订号同时检查，刷新后的页面也不能覆盖另一页刚保存的修改。

游戏配置表更新后，挂机启动及任务检查点会核对已保存的英雄、城市、配方、作物等选项。已不存在的选项会阻止执行，并在配置页提示具体字段；原值保留，重新选择并保存后再开始挂机。资源版本不可用时仍可打开配置页查看和修改设置。资源更新成功后，控制台会取消尚未发送的旧计划，按新表重新规划挂机；若更新失败或配置需要修正，则停止并显示原因，处理后重新开始挂机。

挂机配置修改后自动保存，无须点击保存按钮：停止输入约 0.6 秒后合并提交，保存期间继续修改会排队保存最新内容，导入通过校验后也会自动保存。保存进度仅更新顶部常驻状态文字，不再反复展开成功提示条；状态文字保持单行，避免保存时页面跳动。输入不完整或校验失败时保留更改，修正后自动重试。网络失败最多自动重试 3 次，持续失败时提供重试入口；出现多页面版本冲突时，刷新页面可读取最新配置，当前页面未保存的修改会被丢弃。开始任务或切换账号前会等待保存完成，关闭网页时仍有未完成保存会提示。保存只更新当前账号，不启动挂机。只读预览按当前配置读取真实游戏状态并计算计划，不发送资源操作。执行前仍会复查，预览结果可能随游戏状态变化。

联盟与硅矿入口位于 **挂机配置 → 世界 → 联盟 · 募兵与互助／联盟 · 工事捐赠／硅矿**。这些模块的总开关在挂机页，配置页可直接跳转，工事同时要求联盟总开关。联盟商船作为限时活动，全部开关与策略移到 **活动 → 联盟商船**，支持未开放、未连接或暂停时预配置，活动开关独立控制自动执行，不依赖联盟总开关；挂机运行期间到达开放时间即参与，结束后停止，已有设置继续使用。不差钱商人、海商王与超凡英雄的配置统一在 **活动** 各自详情中自动保存。三个硅矿舰队的独立参数、时间和名单都沿用账号自动保存。新增消费总开关默认关闭。各模块的配置与协议说明见项目文档。[项目文档](#项目文档)

挂机页的模块开关点击后立即保存。页头间隔也按账号自动保存，刷新或重启后继续保留。修改挂机开关、页头间隔或开始挂机、恢复托管前会先自动保存待提交的详细配置，校验失败或版本冲突时会提示处理。网页挂机默认持续循环，支持重启后自动恢复。暂停挂机后可点击 **开始挂机** 重新运行，暂停托管后需点击 **恢复托管** 才会继续运行。

已结束的限时活动会从挂机配置和挂机任务列表中隐藏，并停止相应自动任务；原开关、参数、导入导出字段和实现代码均保留。服务器再次下发当前开放的对应子活动时，后台按原设置恢复，重新载入配置即可看到对应入口，其他尚未开放的子活动继续隐藏。刷新活动状态不会覆盖未保存的配置草稿。

2026-11-12 已下线截至 11-11 的酆都诡事联动配置，包括走江踏浪、酆都法旨、驱邪除祟、龙王罗盘及联动签到/礼包。首届海上风采大赛公告投票期截至 11-12，当日核查时曾暂留入口；2026-11-18 起移除挂机配置固定页签，三个开关统一在活动详情中编辑并保留原值，期次按服务器时间展示，未开放与已结束期次默认收起。满减商店公告期截至 11-13，本工具未设置其自动消费入口。周活动、海商王、军备竞赛及按账号或区服开放的活动不受影响。官方时间依据和恢复规则见 [活动配置下线记录](activity-availability.md)。

原有的联盟订单、联盟情报、博物馆和海兽细项独立保存。装备自动锻造总开关下可分别选择领取与续产，原生模式优先并暂停本组工具策略。博物馆探宝与联盟情报在挂机页各合并为一个总开关，在挂机配置中选择原规则或详细策略；关闭总开关同时暂停两条路径，重新开启不会丢失选择。为兼容旧账号，这两个总开关缺省为开启，但不会额外开启任何消费细项；未选择动作时会提示先配置。对应详细模块生效时接管同一功能，防止新旧路径重复执行。缺省字段升级时补齐，已有显式开关值不重置。基地总开关只管理基地动作；英雄自动养成由挂机页的一个开关统一启停，配置中只选择养成动作、目标与资源保留。

硅矿追杀在 **挂机配置 → 世界 → 硅矿 → 对应舰队** 开启，每行填写一个完整昵称。指定名单优先于空位，只攻击名单内且符合限制的玩家，没有合规目标时可占空位；安全名单、同盟保护、只占空位、矿级、战力及预算限制仍优先。首次产矿前游戏不允许撤退，选择“发现名单目标先撤再打”也需先等首奖；撤回并确认回港后重新核对目标，返航期间不会强行出征。追杀按两分钟检查并响应相关推送，不限于原有三日周期的黑名单追击窗口；矿位协议没有玩家 ID，同昵称无法进一步区分。

**钻石总开关默认关闭**，每日总预算默认 `2000`，钻石保留阈值默认 `0`；日预算为 `0` 时禁止自动花钻石。总开关不会替你开启点金、付费扫荡或购买等项目。各项目限制与总预算同时生效，建筑、工厂等使用加速器时共用保留数量。

配置在 `data/automation-settings.json`，持久用量与防重记录在 `data/automation-usage.json`，按账号保存、北京时间零点换日。发送前先占用预算；明确未发送或拒绝才释放，已发送但结果未知的操作保留占用，带防重键的未知任务跨日继续等待确认。保存配置或重启不会清除这些记录。本工具用量不等于游戏内全部消费，升级前和在游戏里直接进行的消费不计入工具总账。

材料、金币和舰队预留与持久账本配合，避免多个玩法重复使用旧余额。业务确认后仍须取得随后完整的库存或资源快照；读取失败、数据不完整、切号或结果未知时继续保护。联盟互赠及商人订单补料在已收到明确回执后，可于后续读取恢复确认；完全丢失回执且没有可归属本次操作的证据时，仍保留防重记录。配置页导出只含玩法设置，不含登录凭据或用量账本；账号页导出含登录凭据，可选择同时包含配置，仍不包含用量账本。

战报奖励的新旧开关共用同一领取流程与持久防重记录，挂机时任一开关开启即可检查，同时开启也只执行一次。手动活动、单次领奖、挂机和推送共用该记录，任一入口领取结果未知时，后续检查继续等待确认，不会通过另一入口重发。

## 数据与安全

- `data/`：账号、设置、用量账本和本地日志，含登录凭据，不要提交或外发。
- `work/`：游戏协议、配置和素材缓存，不随仓库分发。
- `certificates/`：抓包 CA、目标证书和代理备份，路径按项目位置计算，不依赖盘符；可用 `CW_CA_DIR` 指向其他目录。抓包结束并移除证书后自动清理，选择保留 CA 时保留。
- `src/ui/dist/`：控制台页面构建产物，随源码提交。
- 控制台默认只监听本机回环地址，页面与接口需要密码登录，固定密码为 `123456`；通过 `CW_HOST` 开放其他接口后，仅使用可信局域网或带鉴权的隧道。
- 账号导出和礼包兑换状态文件可能包含凭据或账号信息，请留在本机。

| --- | --- |
| `npm run build:ui` | 修改 TSX、页面脚本或主题样式后生成页面与样式 |

| `npm run check:ui` | 使用 Biome 检查已迁移客户端代码与配套测试 |
| `npm run test:client:browser` | 使用隔离账号验收账号卡片登录设置、独立保存和草稿隔离 |
| `npm run test:startup` | 检查环境与依赖准备、自备协议包、控制台地址和终端输出 |
| `npm run test:core` | 核心协议、日常、原有玩法、阵容和掉线处理回归 |
| `npm run test:progression` | 装备、情报、联盟订单、博物馆、海兽、藏品、资源预留和迁移接线回归 |
| `npm run test:extra` | 详细配置、活动、调度、战后维修、城战/锻造、礼包与地图等额外回归 |
| `npm run test:capture` | 原始抓包、代理、锁和抖音 CLI 回归 |
| `npm run test:wechat` | 微信抓包与登录 CLI 回归 |
| `npm run test:wxapkg` | 微信小游戏包解密与解包回归 |
| `npm run sync-config` | 从本机微信缓存同步配置表到 `work/` |
| `npm run sync-resources` | 立即检查并更新配置表和世界地图 |
| `npm run sync-art` | 同步游戏素材；缺图时可加 `-- --fetch` 从 CDN 补齐 |
| `npm run capture:douyin` | 单独采集电脑版抖音登录样本 |

| `node src/app.mjs probe` | 连接并读取探测信息 |

`npm test` 需要本机可读取游戏协议包；没有协议缓存时，可在电脑版微信打开一次游戏，将自备 `_src_chunks_.wxapkg` 放到程序根目录或 `protocol/`，或设置 `CW_PROTO_BUNDLE` 指向协议包或解包后的 `game.js`。
