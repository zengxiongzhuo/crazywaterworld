# 微信原生扫码登录

在“账号 → 添加账号 → 微信扫码”中生成二维码，用手机微信核对应用宝授权提示并确认，然后选择游戏区服和角色保存。电脑微信和电脑抖音采集入口继续保留。

此实现直接运行在项目的 Node.js 进程中。二维码与授权回调通过 HTTPS 获取，小游戏 code 通过原生 MMTLS 协议取得，再交给游戏渠道接口换取游戏凭据。没有额外的 Go/EXE/DLL、HTTP 服务、监听端口、SQLite 或授权管理后台，也不会下载第三方授权程序。扫码本身不需要浏览器自动化、系统代理或证书安装。

## 生命周期与数据

- 二维码有效期为五分钟；扫码确认后另有两分钟完成授权交换，成功后另有十分钟选择角色并保存。
- 取消、刷新、关闭弹窗或关闭控制台会中断未完成请求并释放临时连接；迟到响应不能恢复已取消的二维码或凭据。
- 微信授权 Cookie、登录票据、MMTLS 密钥、小游戏一次性 code 仅留在当前登录的内存中，不进入账号接口响应和日志，也不落盘。
- `data/wechat-device.json` 仅保存本机随机设备种子，不含微信账号、票据或令牌。以临时授权身份摘要派生每个账号的稳定协议设备，避免每次扫码都随机更换设备；损坏的种子文件会报错，不会静默覆盖。
- 用户保存角色后，游戏登录凭据才进入现有账号库。同一 openId 的微信扫码和旧电脑微信采集账号复用同一条记录，保留人工备注和已保存配置；新账号默认不挂机。
- 读取角色会连接游戏，可能使同账号的游戏客户端下线。二维码授权成功不等于游戏角色已经保存。

## 范围

目前限定应用宝微信授权和《疯狂水世界》的小游戏 code。其他授权渠道、公众号/H5、手机号授权、云函数、账号长期保活及自动换取授权均不在此实现内。游戏协议包仍按项目现有方式从微信缓存或 `CW_PROTO_BUNDLE` 加载。

游戏渠道交换使用单独定义的 `WECHAT_GAME_PROFILE`。其中客户端版本和设备字符串是参考渠道的线协议字段，不是对运行电脑系统版本的探测；服务器兼容性需通过实际扫码确认。

## 验证与来源

`npm run test:wechat-native` 运行二维码、MMTLS、小游戏取码、登录控制器、HTTP 账号保存和界面专项，使用固定协议向量、标准加密向量、假网络以及本机回环服务。专项同时纳入核心离线回归。离线测试不能代替真实微信授权及游戏登录验收。

2026-11-19 在 Node.js 22.17 上通过完整核心离线回归及桌面/手机浏览器验收；真实接口的二维码获取、MMTLS 握手，以及用户参与的扫码授权 → 小游戏 code → 游戏登录凭据交换均已验证成功。该诊断会话没有保存账号或连接游戏角色，真实角色读取与保存仍需在控制台完成。

授权失败会显示固定阶段诊断码，例如 `WX_CALLBACK_REDIRECT` 或 `WX_TICKET_REJECTED`，并在控制台日志中保留同样的脱敏信息。只记录阶段、错误类别及安全的数字状态码，不记录 Cookie、code、票据或上游响应正文。完成修复后需重启原控制台进程才能加载新逻辑。

界面验收命令为 `npm run test:wechat-native:browser`，使用已有 Chrome/Edge 和模拟二维码，不下载浏览器，也不连接真实账号。
