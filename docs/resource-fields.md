# 资源田：玩法与自动化依据

本说明依据项目当前加载的游戏配置，以及本机已提取的客户端逻辑。配置会随赛季和资源版本变化，程序应读取当前表与服务器响应，不把下述示例数值作为永久规则。

## 玩法

- 资源田有三种：工厂产科技点、绿洲产种子、油罐产汽油。成功占领后提供持续产出；当前协议没有独立的资源田领奖请求。
- 只能攻占本联盟城市范围内、本人尚未占领的资源田。客户端按本人的占领列表判断“已占领”，没有读取其他玩家的资源田所有者，也不能把地图上的“本人未占”写成已确认的公共空位。
- 数量上限以 `MyResFieldsResponse.info.maxNum` 为准。配置中的初始数量是 10，联盟科技“资源地数量”可以提高上限。
- 普通资源田的等级取城市配置 `resLevel`，联盟主城周边资源田的等级取对应联盟等级。产量根据场景、赛季、类型和等级查询；当前配置示例为 1 级 360／小时、8 级 780／小时、15 级 1,200／小时。
- 城市被其他联盟占领后，已占资源田仍可能留在个人列表，但会失效并停止产出。总览必须区分有效、失效和城市归属未同步；不能把所有已占田的理论产量当成实际有效产量。
- 攻占需要派遣闲置且耐久大于零的舰队。客户端按所选舰队数量计费，当前 `WorldParamCfg` 中“资源地消耗汽油”为每队 300，“资源地消耗耐久”为 0。耐久固定消耗为零不代表战斗必胜。
- 推荐战力来自 `ResFieldTypeCfg.suggestPower`，只是游戏的建议值。主城资源田即使产量等级较高，客户端仍显示同类型 **1 级**配置的推荐战力；普通资源田使用自身等级。

资源田是持续收益玩法，优化顺序通常是先补足数量、按需求分配三类资源、再选择可打赢的高产田。汽油、种子和科技点不能直接视作等价资源，因此“最大收益”需要用户指定资源偏好。占领的汽油成本、战斗风险、舰队占用时间和城市归属变化也会影响实际收益。

## 项目自动化

总览默认仅显示占领数／上限，以及汽油、种子、科技点三类资源的已占数量、有效基础小时产量和失效数量。各类型明细默认折叠，管理弹窗以“已占资源田”和“可占资源田”两张表展示：可以直接查看本人每块田的资源、等级、城市、格子、有效时产与状态，逐行选择替换或放弃；候选表支持筛选与分页。显示的是基础配置产量，不替代服务器世界资源总产速；世界资源总产速还可能含城市与其他加成。

管理弹窗支持新增占领、手动替换和单独放弃。新增占领保留已有田；替换先点击已占表某行的“替换”，再从候选表选新田，确认页同时展示两块田、有效产量变化、汽油费用和舰队。跨资源替换分别展示增加与减少的资源，不能把汽油和种子的数量直接相减。

可占表仅展示本次同步中满足占领条件的目标；待确认任务锁定、没有可用舰队、汽油不足或名额不足等不可操作目标会隐藏，数量和分页按过滤后的结果计算。名额满时，选择一块有效旧田进行替换后才显示可替换目标。已占表保持完整，仍可逐块放弃。实际发送前仍会重新核对条件。

单独放弃只对确认页指定的一块本人已占田发送放弃请求，不消耗汽油，也不需要空闲舰队。确认后会失去该田和对应产出，只有服务器占领列表确实移除该格才报告成功；结果未知时保留防重记录，不会重复放弃。已有替换或放弃操作尚未确认时，该田不能同时再执行另一操作。放弃不改变自动化配置；若自动补位仍开启，后续可能再次占领符合策略的田地，确认页会提醒。

替换按“放弃旧田 → 确认旧田已移除 → 重新核对条件 → 派遣新田”执行。它不是游戏提供的原子交换：旧田放弃后，如果新出征失败或战斗失败，旧田不会自动恢复。弹窗会明确提示这一点，结果也会区分放弃未确认、旧田已放弃但未出征、派遣待确认和派遣已确认，不把派遣成功写成替换成功。确认绑定原来的旧田、新田和所选舰队，重复提交不会重复放弃或出征。

放弃结果未知时保留旧田替换记录、舰队和名额。后续只读同步若确认旧田已消失，且该操作已结束、尚未尝试出征，会释放未花汽油与舰队占用并提示重新选择，不自动继续替换。已经尝试出征且结果未知的记录继续等待派遣或占领证据；只完成放弃的替换会暂停当天自动补位，避免自动任务立即占用刚释放的名额。

快捷占领与持续自动化在发送前重新核对城市归属、个人占领列表、容量、实际汽油库存与待确认消费、舰队状态和其他任务的预留。地图和城市信息缺失时不凭静态配置认定可攻占；雷达事件占用的资源格暂不派遣。自动化默认关闭；保存配置不会启动挂机。

在 **挂机配置 → 世界 → 资源田** 选择分配方式。两种方式分别保存汽油、种子和科技点的设定。

- **按比例** 将服务器返回的占领上限按三个相对权重分配。先取各自的整数部分，再将余下名额按权重从高到低依次补给有权重的资源。同权重按汽油、种子、科技点的顺序分配。新账号默认权重为 3∶1∶6。例如上限为 10，设为 0∶1∶2 时，目标是 0 块汽油田、3 块种子田、7 块科技田。
- **按配额** 直接填写每类的目标块数。配额合计小于上限时可以留空位，超过上限时受实际容量约束。两种方式中，设为 0 的资源都不会新增占领。

升级旧配置时，原来的优先资源权重设为 3，另外两种各为 1。原有参与舰队和检查间隔继续生效。

**失地后自动补齐** 默认关闭。挂机会记住已同步的本人占田。某块田从本人列表消失，或因城池失守而停产，关闭时保留这部分缺口，仍可首次占田、使用新增名额和升级其他有效田。开启后按当前比例或配额重新补足，从符合条件的同类资源田中优先选高级田。游戏提供本人持有列表及城池归属，程序据此判断失地。

每轮重新读取田地、归属和舰队状态，已出征待确认的田计入分配。有缺口时从符合条件的最高等级开始选，高等级田不可用时再选低等级。满额且配置有缺口时可用超额资源的旧田换入缺少的类型。达到目标后，若同类出现可占的更高级田，也会自动替换已占低级田。调低配额后，只有选好可派遣的新田才会自动放弃旧田。

每次检查最多派一队。自动占领与换田均受参与舰队、最低耐久、预留舰队数量、最低田地等级、推荐战力和可用汽油约束。换田先放弃旧田，确认移除后再核对派遣条件，新田最终以服务器占领列表为准。新账号默认每 60 秒检查一次。手动快捷占领可独立使用。

防重复与失败控制：

1. 发送前持久记录目标与舰队占用，未确认的请求跨轮、重连和跨日继续保留，不因刷新时看到舰队空闲就重发。
2. `SCResFieldCampaignEnd.isWin` 可以证明本次战斗胜负；实际占领成功以 `SCResFieldInfo.info.fields` 或重读 `MyResFieldsResponse.info.fields` 包含目标格为准。
3. 本实现不根据单个战斗推送直接结算，而是重新读取目标和舰队。已确认派遣后，若舰队归队而目标仍未占，本日全部自动占田暂停，避免不断换格消耗汽油；该格本日也不允许再次快捷派遣，次日重新检查。
4. “已确认派遣、舰队归队、目标仍未占”不等于收到明确战败回包，界面和日志只说明尚未确认占领。结果未知且从未确认派遣的记录不会因跨日自动清除。

关闭资源田自动化或离开总览不会取消已发出的任务。公共舰队结算会继续只读核对资源田和舰队，返航后释放已确认任务的舰队锁，并保留当日尝试记录；资源田快照缺失、舰队状态不明或请求结果未知时继续等待证据。

## 协议与配置

| 来源 | 必要字段与用途 |
| --- | --- |
| `MyResFieldsRequest {}` | 返回 `info: {fields: [{gridIdx, cityId, type}], maxNum}`，本人占领与容量。 |
| `WorldInfoRequest {screenCenter: {x, y}}` | `cities: [{id, guildIdx, ...}]`，城市实时归属。联盟编号由精确 `guildId % 1000` 换算。 |
| `AllGuildAbstractionRequest {}` | `guilds: [{id, level, name, ...}]`，主城田等级和联盟名称。 |
| `MyFleetsRequest {}` | `fleets: [{buildingId, state, durability, maxDura, power, curGridIdx, targetGridIdx, treasureLootUid, chipWar, ...}]`；不存在 `battleType` 字段。 |
| `ChallengeResFieldRequest` | `{resFieldGridIdx, fleetBuildingIds}`；无专用成功响应，不把“已发送”当成占领。 |
| `GiveUpResFieldRequest` | `{resFieldGridIdx}`；只允许本人已占格。 |
| `SCResFieldCampaignBegin` / `SCResFieldCampaignEnd` | `{resFieldGridIdx}` / `{resFieldGridIdx, isWin}`，战斗事件。 |
| `SCResFieldInfo` | `{info: {fields, maxNum}}`，最新个人占领列表。 |
| `SCWorldRes` | `{resOutputs: [{itemId, speed}]}`，服务器世界资源总产速，不能直接归因给资源田。 |
| `<scenario>_CityCfg` | `{id, name, level, resLevel, guildIndex}`。`guildIndex > 0` 为联盟出生主城配置。 |
| `<scenario>_ResFieldTypeCfg` | `{season, type, level, suggestPower, resId, product: [resourceId, perHour]}`。 |
| `ResFiledBaseCfg` | `{id, name, resPath}`，注意游戏表名拼作 `Filed`；该表没有战力字段。 |

静态地图只给资源类型、城市与格子，不给实时归属。项目地图解析在 `src/world.mjs`；既有基础产量计算在 `src/resource-fields.mjs`。`tools/fixtures/resource-fields.mjs` 使用虚构账号、地图和真实 protobuf 编解码，供离线验证使用，不连接游戏。

`node tools/selftest-resource-fields.mjs` 覆盖个人归属、收益失效、主城战力、雷达事件格、舰队与消费互斥、快捷确认、重复防护、未知结果跨日／账本重载、自动策略、合服门控，以及自动化关闭后的公共结算、跨世界隔离和迟到快照保护。离线测试不表示已对真实账号执行占领。
